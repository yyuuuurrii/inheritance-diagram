# 相続関係図スキル（法定相続情報一覧図・相続関係説明図）

司法書士業務の補助ツール。ユーザーが文章で伝えた家族関係を Claude が解釈して `case.json` にし、
`python -m souzoku_zu build` で図とチェックリストを機械的に作る。**図は Claude が描かない**（毎回同じ品質にするため）。

## 役割分担

| 担当 | やること |
|---|---|
| Claude | テキストの解釈 → `case.json` 作成、出力の目視確認、チェックリストの要約、修正の反映 |
| プログラム | 相続人の判定・相続分の計算、レイアウト、PDF/PPTX/PNG 出力、チェックリスト生成 |
| 司法書士（ユーザー） | 図とチェックリストを見て、正誤を最終判断 |

## 手順

1. **準備（初回のみ）**：`pip install -r requirements.txt`（このリポジトリのルートで）。
   明朝体が必要なら `apt-get install -y fonts-ipafont-mincho`（なければゴシック体で出力される）。
2. **テキストを受け取る**。止まって質問するのは次の場合だけ。それ以外は進めて、判断した点を `interpretation_notes` に書く。
   - 誰が被相続人かわからない
   - 被相続人の死亡日がない（相続人の判定ができない）
   - 親子・夫婦関係が2通り以上に読めて、**判定結果が変わる**場合
3. **`cases/<案件名>/case.json` を書く**（`cases/` は .gitignore 済み。実案件はコミットしない）。形式は下の「入力形式」。
4. **実行**：`python -m souzoku_zu build cases/<案件名>/case.json -o cases/<案件名>/out`
5. **自分で PNG を Read して見る**。線の交差、文字のはみ出し、つながる相手の誤りがないか。
   レイアウトが崩れていたらユーザーに出す前に直す（データの誤りを先に疑う）。
6. **ユーザーに渡す**：PNG（プレビュー）と PPTX（編集用）と PDF を `SendUserFile` で送る。
   あわせて `確認チェックリスト.md` を送り、チャットには次を短く書く：
   - 相続人と法定相続分（表）
   - 「判断が必要だった箇所」「解釈メモ」「入力不足」の要点
   - JSON は見せない（ユーザーは JSON での確認を望んでいない）
7. **修正を受けたら** `case.json` を直して 4 から繰り返す。

## 入力形式（case.json）

```json
{
  "decedent": "taro",
  "created_date": "R7.11.6",
  "creator": {"title": "司法書士", "name": "氏名", "address": "事務所住所"},
  "options": {"child_relation_style": "koseki", "show_heir_address": true,
              "show_shares_in_explanation": false, "font": "mincho"},
  "interpretation_notes": ["「〜」を〜と解釈しました"],
  "persons": [
    {"id": "taro", "name": "法務　太郎", "sex": "M", "birth": "S15.1.1", "death": "R6.3.1",
     "address": "最後の住所", "honseki": "最後の本籍"},
    {"id": "hanako", "name": "法務　花子", "sex": "F", "birth": "S20.5.5",
     "address": "住所", "relation": "妻", "applicant": true}
  ],
  "marriages": [{"a": "taro", "b": "hanako", "date": "S46.4.1", "divorced": null}],
  "parent_child": [{"parent": "taro", "child": "ichiro", "type": "biological"}]
}
```

- **日付**：`S20.1.1` / `昭和20年1月1日` / `1945-01-01` のどれでもよい。わからない項目は書かない（図に「（未入力）」と出て、チェックリストに載る）。
- **id**：英数字の短い名前（`taro`, `hanako`, `c1` など）。
- **name**：ユーザーが書いた漢字のまま。旧字体・異体字を勝手に新字体にしない。姓と名の間は全角スペース。
- **relation**：主たる被相続人から見た戸籍上の続柄（長男・二女・養子 など）。わかるときだけ書く。
- **relation_by**：数次相続の2次相続など、別の被相続人から見た続柄 `{"hanako": "長男"}`。
- **親子は親ごとに1行**。父母とも書く（片方しか書かないと「片親だけの子」として描かれる）。
- フラグ：`renounced`（相続放棄）、`disinherited`（廃除）、`disqualified`（欠格）、`applicant`（一覧図の申出人）。
- `estate_note`：説明図に付ける注記（「相続」「分割」など、遺産分割の結果）。

### 複雑なケースの書き方

| 状況 | 書き方 |
|---|---|
| 前妻の子 | 前妻を persons に入れ、`marriages` に `divorced`（離婚日、不明なら `true`）。子は父・前妻の両方と親子 |
| 婚外子 | 被相続人と母の親子を書く（婚姻は書かない） |
| 代襲相続（子が先に死亡） | 子に `death`、孫を子の子として書く。判定は自動 |
| 孫養子（孫を養子に） | 孫を「実親（子）の子」と「被相続人（と配偶者）の養子」の両方で書く。`type: "adopted"` と縁組日 `date`。二重資格は自動判定 |
| 婿養子・嫁養子 | 子の配偶者を `marriages` で結び、被相続人との `adopted` も書く。図では兄弟と並べて二重線 |
| 養子の子（縁組前に出生） | 生年月日と縁組日を必ず入れる。代襲できないことを自動判定 |
| 離縁 | `parent_child` に `dissolved`（離縁日） |
| 兄弟姉妹相続・半血 | 被相続人の**父母を必ず入れる**（全血・半血の判定に必要）。後妻・後夫も入れる |
| 数次相続（相続人が後に死亡） | その人の `death` と、その人の相続人（配偶者・子）も入れる。一覧図は被相続人ごとに自動で分かれる |
| 相続放棄 | `renounced: true`。一覧図には載り（戸籍ベースのため）、説明図に「相続放棄」と出る |
| 子全員が放棄 → 父母・兄弟へ | 父母（兄弟）も入れる。順位の移動は自動 |

## 出力

`out/` に以下ができる。

- `01_法定相続情報一覧図_<被相続人>.pdf/.pptx/.png`（数次相続があれば 02, 03… と被相続人ごと）
- `NN_相続関係説明図_<被相続人>.pdf/.pptx/.png`
- `確認チェックリスト.md`

PPTX は PowerPoint で開いて、そのまま文字の修正・移動ができる（人物ごとのテキストボックスと直線）。

## 注意

- 判定ロジックは民法 887〜890・900・901 条ベース。二重資格・欠格・同時死亡などはチェックリストに要判断として出る。**最終判断は司法書士**。
- 一覧図の様式（A4 縦、下部の余白、記載事項）は法務局の記載例に寄せているが、法務局の原本ファイルとは照合していない。管轄法務局の最新の記載例を一度確認すること。
- 判定だけ見たいときは `python -m souzoku_zu check case.json`。
